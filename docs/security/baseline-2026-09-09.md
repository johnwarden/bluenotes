## Verified findings

Tried to disprove each candidate. Items below survived.

### V1 — Production Fly deploy: mutable action tag + `curl \| sh` + no workflow `permissions`

- **Where:** `.github/workflows/build-and-push-bluenotesweb-flyio.yaml:18`, `:50` (`actions/checkout@v4`); `:53–55` (`curl -L https://fly.io/install.sh \| sh`); workflow has **no** `permissions:` block. Triggers on `push` to `release` (the ship tip).
- **Attacker input:** Compromised or retagged `actions/checkout` v4, or a hijacked `fly.io/install.sh` response, during a production deploy job that already holds `secrets.FLY_API_TOKEN`.
- **Impact path:** Job runs as the default `GITHUB_TOKEN` (unscoped) **and** deploys `bluenotes.social` with Fly. Pre-job runs lint / typecheck / `pnpm build-web` but **not** `pnpm test`. `concurrency.cancel-in-progress` is `false` (two deploys can race). Other workflows in this repo pin actions to 40-char SHAs; this one does not.
- **Protections:** Deploy job uses `environment: production`. Pre-deployment compile gates some bad trees. Not “deploy without any CI,” but weaker than `lint.yml` (which pins SHAs, sets `permissions: contents: read`, and runs tests). AWS/EAS image workflows are gated `github.repository == 'bluesky-social/social-app'` and do not ship this fork.
- **Confidence:** High (config is in-tree). **Impact:** High (production deploy + Fly token).
- **Smallest fix:** Pin `actions/checkout` to the same SHA as `lint.yml`; install a versioned `flyctl` with checksum; set `permissions: contents: read` (and only what Fly needs); add `pnpm test` to `pre-deployment` or require the PR “Run tests” check before `release` moves; set `cancel-in-progress: true` on `group: production-deployment` (or `deploy-production` per `AGENTS.md`).
- **Proposed regression test:** Workflow lint (zizmor already exists) must fail if this file uses a floating tag or `curl | sh`. Do not merge that here.

Semgrep independently flagged the same file: `gha-curl-pipe-shell` (ERROR) and `github-actions-mutable-action-tag` (WARNING).

### V2 — Unauthenticated `getConfig.labelerDid` becomes the global Community Notes labeler (no pin)

- **Where:** `src/state/queries/community-notes-config.ts:61–87` (fetch `org.opencommunitynotes.getConfig`, accept any `string` `labelerDid`); `src/state/queries/community-notes-config-loader.tsx:18–24`; `src/lib/community-notes/labels.ts:23–25`, `:91–96`; `src/state/session/additional-moderation-authorities.ts:91–100`.
- **Attacker input:** Body of unauthenticated `GET {notes}/xrpc/org.opencommunitynotes.getConfig`. In production the host is `https://api.bluenotes.social` (`src/lib/constants.ts:20–24`). No `did:` prefix check (unlike `feedGeneratorDid` in `getNotesServiceAudience`). Query is `staleTime: Infinity` for the session — first response wins.
- **Impact path:** Loader calls `updateCommunityNotesLabelerDid(labelerDid)` then `configureAdditionalModerationAuthorities()`, which appends that DID to `Client.appLabelers`. `isCommunityNotesLabeler` then treats **only** that DID as the CN labeler. A integrity failure of getConfig (compromised notes host, or TLS/DNS failure to that host) swaps which labeler’s `annotation` / `proposed-annotation` labels drive the widget and feed UI for every client that loaded config.
- **Protections:** HTTPS to a fixed prod host for users on any non-localhost, non-staging PDS (`IS_PROD_SERVICE`). Hardcoded fallback DIDs exist (`src/lib/community-notes/labels.ts:14–17`, `did:plc:57fl6zy4wmpuknwpgtjqkvlz`) but are **ignored once config succeeds**. Label *emission* is not done by this client.
- **Confidence:** High for the missing pin / missing DID check. Impact is High **if** getConfig integrity fails; Low if the notes host and TLS are fully trusted.
- **Smallest fix:** Require `labelerDid.startsWith('did:')` and equality (or allowlist) against `COMMUNITY_NOTES_LABELER_DID` for the environment. Refuse to call `updateCommunityNotesLabelerDid` on mismatch.
- **Proposed regression test:** Extend `community-notes-auth-test` / a new config-loader test: getConfig returning `labelerDid: 'did:plc:attacker'` must not change `getCurrentCommunityNotesLabelerDid()` away from the pinned prod DID; non-DID strings must throw.

### V3 — `getConfig.feedGeneratorDid` is used as `getServiceAuth` audience with no pin

- **Where:** `src/lib/api/community-notes-auth.ts:135–157`, `:211–223`, `:263–276`. Cached 1 hour per notes origin.
- **Attacker input:** Same unauthenticated getConfig. `feedGeneratorDid` must be a string starting with `did:` (stronger than V2) but is **not** compared to a known notes-service DID.
- **Impact path:** Signed-in OAuth clients mint `com.atproto.server.getServiceAuth({ aud: <config DID>, lxm })` at the **user’s PDS** and send the JWT to the notes host. A compromised notes host can name an attacker-controlled `aud` and receive a notes-bound (or attacker-aud) service-auth JWT for the victim. Password sessions send the PDS `accessJwt` to the notes host instead (notes is expected to verify via PDS `getSession`).
- **Protections:** Writes use `requireAuth: true` (`propose` / `vote` / `deleteNoteRating`). Soft-anon only on `getProposals` if mint fails. Client does not send empty Bearer. Tests in `src/lib/api/__tests__/community-notes-auth-test.ts` cover mint/`requireAuth` but not audience pinning.
- **Confidence:** High for missing pin. Impact Medium–High given notes-host compromise (defense in depth).
- **Smallest fix:** Pin `aud` to the known notes DID (document it next to `COMMUNITY_NOTES_LABELER_DID`). Reject getConfig audience drift.
- **Proposed regression test:** `getNotesServiceAudience` / `mintNotesServiceAuthForUrl` must reject a `feedGeneratorDid` that is a well-formed DID but not the pinned notes DID.

### V4 — `bskyweb` IPCC HTTP client disables TLS verification

- **Where:** `bskyweb/cmd/bskyweb/server.go:149–154` (`ipccClient` `TLSClientConfig.InsecureSkipVerify: true`). Used by `WebIpCC` (`:396`, `:975–983`) and geolocation helpers (`bskyweb/cmd/bskyweb/geolocation.go:118`, `:147`). Fly deploy sets `GEOLOCATION_URL=/ipcc` (workflow `:76`).
- **Attacker input:** Network position between the Fly VM and `ipccHost` (or the public IP-geo fallbacks `ipapi.co` / `ip-api.com` in `geolocation.go`).
- **Impact path:** Forged country/region for `/ipcc` and Web geolocation. That feeds `configureAdditionalModerationAuthorities()` (`src/state/session/additional-moderation-authorities.ts:73–79`), which selects which extra labelers are attached for a country. Semgrep `bypass-tls-verification` (WARNING) is a true positive; `missing-ssl-minversion` on the same block is secondary.
- **Protections:** Fly terminates user TLS (`fly.toml` `force_https`). This skip is on the **server’s outbound** IPCC/geo calls, not the browser. Sitemap client does **not** skip verify.
- **Confidence:** High. **Impact:** Medium (moderation-authority set and age-geo flags; not account takeover).
- **Smallest fix:** Remove `InsecureSkipVerify` (or gate it to `debug`). Keep verify-on by default.
- **Proposed regression test:** Fail CI if `InsecureSkipVerify` appears outside a `_test.go` / debug-only constructor.

### V5 — Historical secrets in git (none in current tree)

- **Where (history only):** `eas.json` at `c75c888de240` — Semgrep/gitleaks `sentry-access-token` (commit message: Sentry setup, “paul’s auth tokens”). Segment-style `generic-api-key` in old `src/lib/analytics*.tsx` / `segmentClient.ts`. `src/state/auth.ts` / `src/api/auth.ts` early UCAN/auth keys. **63 / 77** hits are YouTube/TikTok HTML **test mocks** (`__tests__/lib/__mocks__/youtube*.ts`, `tiktokHtml.ts`) — treat as false positives / public embed keys.
- **Attacker input:** Clone of the public repo + history.
- **Impact path:** If those Sentry tokens were never rotated, they remain valid from git. Current `eas.json` has **no** auth tokens. `gitleaks dir` is clean. `code-signing/certificate.pem` is a **public** `BEGIN CERTIFICATE` (Bluesky), not a private key.
- **Protections:** Tokens are not in HEAD. GitHub Actions secrets are referenced by name only.
- **Confidence:** High that history contains the 2022 Sentry tokens. Unknown whether they still work (no production check).
- **Smallest fix:** Rotate any Sentry / Segment tokens that ever lived in this fork’s history. Optional `.gitleaks.toml` allowlist for the YouTube mock fixtures only.
- **Proposed regression test:** `gitleaks dir` in CI on PRs (current tree). Do not fail CI on historical YouTube mocks without an allowlist.

## Plausible concerns

### P1 — Client writes are “logged in,” not “authorized”

`propose` / `vote` / `deleteNoteRating` (`src/lib/api/community-notes.ts:173–181`, `:245–247`, `:408–429`) require a session and `requireAuth: true`. They do **not** check note authorship, rater identity, or labeler role. The body is caller-chosen `targetUri` / `noteUri` / `note` text. AID is documented as server-derived (`:183–184`). **Cannot confirm** from this repo that the notes service refuses cross-account edit/delete or forged `typ`/`val`. Hypothesis “someone can manipulate another person’s notes” is **open** until the notes service is reviewed.

### P2 — Note and post text rendering

CN note bodies use `TextWithLinks` (`src/components/CommunityNotes/CommunityNoteWidget.tsx:396–399`, `src/components/TextWithLinks.tsx`). URLs must match `https?://` (no `javascript:`). Render path is React Native `Text` / `InlineLinkText`, not HTML. **No** `dangerouslySetInnerHTML` / `innerHTML` under `src/`. HTML XSS via note text is **disproved** on this client. Remaining risk is ordinary `https://` phishing links (product-accepted) and server-side HTML in `bskyweb` embed snippets (`bskyweb/cmd/embedr/snippet.go:61–69`: `template.URL` around handle/rkey; PostText is a string field — review if that template auto-escapes).

### P3 — Echo `%2F` static bypass (CVE-2026-55677 / GHSA-vfp3-v2gw-7wfq)

`bskyweb` uses `github.com/labstack/echo/v4@v4.13.4`. OSV rates this HIGH. `/static/*` is public cache-control only (`server.go:285–304`). Optional BasicAuth is global `e.Use`, not route-level. **No verified extra exposure** of hidden static files on the current route table. Upgrade Echo anyway.

### P4 — `jwx/v2@2.0.12` (indirect via indigo)

DoS / panic CVEs (CVE-2023-49290, CVE-2024-21664, CVE-2024-28122). Indirect in `bskyweb/go.mod`. No evidence this process parses attacker JWE on the public path. Upgrade with indigo.

### P5 — Container runs as root

`Dockerfile:132–139` — Semgrep ERROR `missing-user`. Typical for this image; impact needs a container break. Add a non-root `USER` if Fly allows.

### P6 — `bskyembed` `postMessage(..., '*')`

`bskyembed/src/components/container.tsx:26–28` sends `{height, id}` to any parent. Low confidentiality; classic embed pattern. Tighten origin if the embed is only expected on known hosts.

### P7 — Dependency flood (after splitting the root lockfile)

Supplemental OSV on the app lockfile: `@xmldom/xmldom` 0.8.13/0.9.10 (many HIGH), `undici@6.25.0`, `tar@7.5.15` (CRITICAL DoS), `shell-quote@1.8.3` (CRITICAL quote/newline), `serialize-javascript@6.0.2` (RCE in a **dev** serializer), `webpack-dev-server`, `fast-uri`, `js-yaml`, `linkify-it`. Most look like **dev / transitive** tools, not the RN web runtime. Do not treat the count as “40 production RCE.” Prioritize anything that ships in `pnpm build-web` / the Fly image; confirm with `--call-analysis` / production SBOM (not done).

### P8 — CI secrets on workflows that do not run here

`build-and-push-*-aws.yaml` put ECR username/password in **workflow-level** `env`. Jobs are `if: github.repository == 'bluesky-social/social-app'`. Same for EAS/nightly iOS/Android signing (`EXPO_TOKEN`, `ASC_KEY_P8_BASE64`, Android keystore). Dead for this fork unless those secrets are also configured and the `if:` is removed. `claude-mention.yml` / `claude-review.yml` use `AGENT_GATEWAY_CLAUDE_GH_REVIEW_KEY` against `agentgateway.k1.prod.bsky.dev` (Bluesky infra). Confirm this fork does not store that secret.

## Hardening advice

1. Treat **V1** as the first ship-path change: pin deploy actions, stop `curl | sh`, scope tokens, run tests before Fly, cancel overlapping deploys.
2. Pin Community Notes **labeler DID** and **service-auth audience** in the client (V2/V3). Keep hardcoded constants as the source of truth; getConfig may only confirm them.
3. Enable TLS verify on `ipccClient` (V4).
4. Rotate historical Sentry tokens (V5); add `gitleaks dir` to PR CI.
5. Split or fix root `pnpm-lock.yaml` so it is a single document (scanner + human hygiene). Re-run osv-scanner on the app document in CI.
6. Upgrade Echo and review `bskyweb` static/`%2F` behavior; add CSP (`server.go:188–190` still `TODO`).
7. Notes-service review (separate repo): every write must authorize the **caller DID** vs note/rating author; labeler signing keys must not be on the public XRPC path; reject unexpected `typ`/`val`.
8. Do not enable live bots / production flags from this report.
